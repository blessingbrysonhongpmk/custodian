Build a full-stack web application called "Vanam Kuri" — a tree plantation accountability and survival-tracking platform for India. This is NOT a generic tree-tracking app — it's a responsibility-transfer and community-verification system. Follow this spec exactly.

## CONCEPT
Trees fail not because of lack of tracking, but because caretaker responsibility silently lapses. Vanam Kuri solves this with:
1. Custody Chain — every tree has a responsible custodian; when they leave, a mandatory handoff ceremony transfers responsibility to a successor.
2. Kuri Groups — trees are managed by small community caretaker groups (inspired by Tamil Nadu's traditional chit-fund/kuri trust system), not lone individuals.
3. Peer Verification — checkpoints are verified by a DIFFERENT nearby caretaker, never the tree's own owner, to prevent self-reported fraud.
4. Failure Autopsy — every tree death triggers a structured cause-of-death report that feeds into future plantation planning.
5. Caretaker Micro-Payments — ground-level caretakers earn small verified payouts per confirmed-alive checkpoint.

## DESIGN SYSTEM
- Primary palette: deep forest green (#1B4332), moss/sage green (#52796F, #84A98C), warm cream/off-white background (#F8F6F0), terracotta/amber accent for alerts and CTAs (#C9772A)
- Typography: modern serif for headings (e.g., "Fraunces" or "Playfair Display"), clean sans-serif for body (e.g., "Inter" or "Manrope")
- Style: premium, editorial, nature-journal aesthetic — NOT a generic template look. Soft shadows, rounded cards, subtle organic/leaf-line dividers, generous whitespace. Avoid stock "green eco app" cliches like literal leaf icons everywhere — keep it minimal and sophisticated.
- Fully responsive, mobile-first (most real users will be on phones in the field)
- Smooth micro-animations on state changes (tree status updates, handoff ceremony, checkpoint completion) using Framer Motion

## TECH STACK
- Frontend: React + Vite + Tailwind CSS
- Routing: React Router
- Maps: Leaflet.js with OpenStreetMap tiles (free, no API key needed)
- Charts: Recharts (for survival trend graphs, reliability scores)
- Animations: Framer Motion
- State: React Context or Zustand for app-wide state (mock data, no real backend needed for prototype — use realistic seeded mock data)
- Icons: Lucide React

## PAGES / SCREENS TO BUILD

### 1. Landing Page
- Hero section with a bold headline: "Trees don't need supervisors. They need a Kuri."
- Animated stat comparison: "Self-Reported Survival: 92%" vs "Verified Survival: 41%" — this gap is the emotional hook
- Short explainer of the 3 layers (Custody Chain, Peer Verification, Failure Autopsy)
- CTA buttons: "View Live Ward Dashboard" / "See a Tree's Story"

### 2. Ward/Organization Dashboard
- Map view (Leaflet) showing all tree locations in the pilot ward, color-coded pins: green (verified healthy), amber (at-risk), red (dead/unresolved), grey (orphaned/needs custody)
- Summary cards: Total trees, Verified survival rate, Custody continuity rate, Active Kuri groups, Pending handoffs
- A trend line chart: verified survival rate over the last 12 months
- List of "Kuri Groups" with group trust score

### 3. Tree Passport (individual tree detail page)
- Header: Tree ID, species, planting date, location pin (mini map)
- Full timeline: planting photo → each checkpoint (photo/video thumbnail, verifier name, status) → current status badge
- "Adopted by" section showing current custodian + custody history (past custodians in a visual chain/timeline)
- Support for both photo AND short video upload as checkpoint evidence (video especially useful for showing tree movement/health in wind, can't be a static reused photo)

### 4. Custody Handoff Ceremony screen (the "wow" feature)
- When a custodian's assignment is expiring (show a countdown badge, e.g. "18 days left"), trigger this screen
- Outgoing custodian's care summary card (checkpoints completed, care log)
- Successor nomination + "Accept Custody" button with a small animated ceremony transition (e.g., a growing tree animation, a handshake/passing-torch visual metaphor) — this should feel emotionally meaningful, not like a form submission
- Once accepted, generates a shareable "certificate" style card

### 5. Verification Task Screen
- Shows the caretaker a queue of trees THEY are assigned to verify (never their own trees)
- For each: mini map pin, previous checkpoint photo (for comparison), upload new photo/video, status selector (Healthy / At-Risk / Dead), optional note
- On submit, show comparison side-by-side of old vs new photo/video

### 6. Kuri Group View
- Shows a caretaker group (5-10 members) responsible for a tree cluster
- Group trust score, payout history, member list, per-member verified checkpoint count
- Visual "collective score" meter — group-level accountability, not individual blame

### 7. Risk & Escalation Queue (admin view)
- List of: orphaned trees (no custodian), missed checkpoints, mismatch flags (self-report vs peer-report disagreement)
- One-click "reassign" or "escalate to ward officer" actions

### 8. Failure Autopsy Form
- Triggered when a tree is marked Dead
- Structured dropdown: cause (Drought / Cattle damage / Vandalism / Waterlogging / No custodian / Disease / Other)
- Auto-classifies as "Systemic" (site/species issue) vs "Custodial" (negligence) with a visual badge
- Shows other trees in the same zone with the same failure cause — "3rd cattle-damage death in this zone this season" style insight

### 9. Impact Report / Reliability Dashboard
- Org-level reliability score trend across multiple plantation drives (line chart)
- Verified vs self-reported survival gap over time
- Downloadable-style summary card (just UI, no real PDF export needed for prototype)

## KEY UX DETAILS
- Every checkpoint reminder/notification should be written in a warm, first-person "voice of the tree" tone (e.g., "I'm still here. But it's been 3 months since anyone checked on me.") rather than a dry system alert
- Use festival-calendar styling for community verification events (e.g., a "Kaaval Vizha" banner for a ward-wide verification day)
- Seed the app with realistic mock data: ~40-50 trees across a fictional ward, several Kuri groups, a mix of healthy/at-risk/dead trees, and at least one live custody handoff scenario ready to demo

## WHAT NOT TO BUILD
- No real payment integration — mock the caretaker payout UI only
- No real AI/ML model — if you add a "photo similarity check" feature, mock it with a simple placeholder result, don't fake real computer vision
- No login/auth complexity needed — a simple role switcher (View as: Ward Admin / Caretaker / Verifier) is enough for demo purposes

Build this as a polished, demo-ready prototype optimized for a hackathon judge walkthrough — prioritize the Landing Page, Ward Dashboard, Tree Passport, and Custody Handoff Ceremony screens as the highest-quality, most complete screens since those will be shown first in the demo.
